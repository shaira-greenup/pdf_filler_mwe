# PDF Form Filler

Fills a fixed, known AcroForm PDF from a typed data object. Runtime is **Bun**. Language is **TypeScript**. No build step.

## Scope

This is a minimum working example. One form, one hardcoded data object, one filled PDF written to disk. There is no server, no UI, no upload, no multi-template registry. Do not build those. The same fill code will later run in the browser inside a SolidJS app, so keep the fill logic free of Bun/Node-specific APIs — isolate file I/O at the edges.

## Stack

- Runtime: Bun (native TypeScript, ESM, top-level await)
- PDF: `pdf-lib`
- Validation: `zod` (only from Milestone 3 onward)
- Tests: `bun test` (built in)

Install with `bun add`. Run with `bun run scripts/name.ts`. Never use npm, tsx, ts-node, nodemon, or a bundler. Do not add a build step, do not scaffold with `bun create`, do not add vitest or jest.

## Files

```
fixtures/blank-form.pdf     the real form, committed, never modified
fixtures/fields.txt         field dump, generated by scripts/inspect.ts
fixtures/sample-data.json   realistic but fake input
scripts/inspect.ts          dump fields
scripts/fill.ts             fill and write output
out/                        generated PDFs, gitignored
```

## Hard rules

These are the failure modes that do not announce themselves. Follow them exactly.

1. **Never invent a field name.** Read `fixtures/fields.txt` and use those exact strings. If a required field is absent from the PDF, throw with the missing name. Never fall back to a guess, a fuzzy match, or a silent skip.
2. **Always call `form.updateFieldAppearances()` before `pdf.save()`.** Without it the values render blank in Chrome and mobile viewers while looking correct in Acrobat.
3. **Load with `{ ignoreEncryption: true }`.** Some published forms carry an empty owner password.
4. **Do not flatten.** Not in the MWE. It is a separate variable and pdf-lib's flatten is weak on checkboxes and radio groups.
5. **Do not set calculated fields.** If a field has a JavaScript calculation action, set its inputs instead. Acrobat recomputes derived fields on open and will discard what you wrote.
6. **Radio groups and checkboxes use export values from the PDF**, not `"Yes"`/`"true"`. `scripts/inspect.ts` must print the valid options for every checkbox and radio group, and the fill code must use those literal strings.
7. **Read back every field after writing** and compare to the intended value. Throw on mismatch. This is the cheapest guard against truncation, calculated-field overwrites, and wrong radio export values.
8. **Assert the template hash on load.** Store the SHA-256 of `fixtures/blank-form.pdf` and fail at startup if it changes, so an upstream re-publish surfaces immediately instead of producing blank forms.

## Bun API notes

Use Bun's file APIs at the I/O edges rather than `node:fs`:

```ts
const bytes = new Uint8Array(await Bun.file("fixtures/blank-form.pdf").arrayBuffer());
await Bun.write("out/filled.pdf", await pdf.save());
```

For the template hash:

```ts
const hasher = new Bun.CryptoHasher("sha256");
hasher.update(bytes);
const digest = hasher.digest("hex");
```

## Milestones

Complete each one and stop for review before continuing. Do not run ahead.

1. **Inspect** — `scripts/inspect.ts` prints every field: name, type, current value, and for checkboxes and radio groups the valid export values. Write the output to `fixtures/fields.txt`.
2. **Fill** — `scripts/fill.ts` sets three or four hardcoded fields and writes `out/filled.pdf`. Stop here. The output must be opened and checked by a human in both Acrobat and Chrome.
3. **Map** — a Zod schema for the input shape plus a mapping module from schema keys to exact PDF field names. Replace the hardcoded values with parsed `fixtures/sample-data.json`.
4. **Verify** — a hostile-input test using `bun test`: an accented name, a maximum-length address, every checkbox set. Confirm no throw and no truncation.

## Known hazards

- **Non-ASCII characters throw at save time.** WinAnsi cannot encode them. Curly apostrophes from Word and accented names are the common triggers. Do not paper over this with a `.replace()` that strips characters — surface it, and if it needs solving, embed a font via `@pdf-lib/fontkit`.
- **Duplicate field names across pages share one value.** Setting one sets all. This is by design in the PDF spec, not a bug to work around.
- **Text overflow is silent.** `setText` never complains when a value clips or auto-shrinks past legibility. Only a rendered image reveals it.
- **pdf-lib is effectively unmaintained.** If something is broken at the library level, `@cantoo/pdf-lib` is a maintained drop-in fork. Do not switch to it preemptively.

## Verification

You cannot see the rendered PDF. "The script ran without error" and "the form is correctly filled" are different claims — never report the second based on the first. After any change that affects output, state plainly that the PDF needs to be opened and checked by a human, and say which fields to look at.
